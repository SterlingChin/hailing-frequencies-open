# OpenAI gotchas — shared preparation snapshot

October 9, 2026. Historical results below come from the October 6–7 preparation project; documentation lessons retain their source dates. No provider calls were rerun for this export. This page supersedes the old “generation untested” October 6 summary for preparation history, not for your account.

1. **Model listing and generation are separate checks.** `/models` worked before generation did. Initial generation returned `429 insufficient_quota` / `credit_balance_exhausted`; later chat, Responses and embedding checks passed after credits were added. Those historical balances do not transfer to your key.
2. **Distinguish quota from throttling.** Inspect the structured error. Billing problems need account changes; temporary rate failures may need bounded backoff. Generation responses exposed request/token rate headers absent from metadata reads. [Error guide](https://developers.openai.com/api/docs/guides/error-codes), [rate limits](https://developers.openai.com/api/docs/guides/rate-limits).
3. **Do not add `/v1` twice.** The configured base already includes it. The alpha.10 `/models` regression captured the canonical operation; the older prefix-capture defect is historical.
4. **200 or `completed` does not guarantee usable text.** Tiny reasoning/output budgets produced a reasoning-only response or tool-only output. Inspect content, tool calls, status and incomplete details. Budget backend work and final text separately.
5. **Structured Outputs was exercised later in preparation.** The small chat JSON-schema example returned JSON in `message.content`, which still needs parsing and schema validation. Handle refusals and truncation explicitly. Root object, required properties and `additionalProperties: false` are documented constraints. [Guide](https://developers.openai.com/api/docs/guides/structured-outputs).
6. **Some families need beta headers and compatible models.** Dated tests used `OpenAI-Beta: agents=v1` for agents/vaults/templates and `chatkit_beta=v1` for ChatKit. Agent creation rejected `gpt-4.1-nano` and later accepted `gpt-5.4-mini`. These are historical examples; confirm current eligibility for your project.
7. **Resource state can lag.** A stored completion was initially 404 and visible on a later poll. An auto container remained listed as running after successful DELETE responses. Bound polling and report unresolved cleanup rather than claiming immediate deletion.
8. **A canceled job can leave files.** A canceled batch left an error output file in the preparation. Cancellation timing did not verify billing or a free operation.
9. **Required inputs and status codes can differ from the imported snapshot.** A tested eval create returned 201. Webhook creation required `name` and `event_types`, rejected `description`, and returned a signing secret that belongs only in private storage. Revalidate your exact operation before relying on those results.
10. **Choose uploads and models deliberately.** A `user_data` file-content download was refused while parsed vector-store content worked for an `assistants` file. A short audio fixture transcribed differently on two models; that is one fixture, not a general quality ranking. Multipart image edits and skills hit the client limits in [BUGS](BUGS.md).
11. **Costs are not established by tiny output alone.** Web search and code interpreter add separate usage/resources. No previous “under ten cents” estimate is a verified price for your run. Check provider usage and budgets.
12. **Live readiness remains open.** A historical Realtime client-secret mint did not prove streaming, GPT-Live access, telephony or a complete call. See [VOICE-PREP](../VOICE-PREP.md).

The full stack notes include dated 404/permission results for additional families. A route present in the public spec is inventory, not guaranteed project access. Private evidence is excluded; no inherited operation is marked verified for your account.
